Listing a Rust MCP server in the official MCP Registry

A cargo package, a README line, and one JSON file

Guide · Nov 1, 2026 · Blog

Since July 13, the official MCP Registry accepts Rust servers published to crates.io as cargo packages. Clients can then install them the Rust way: cargo install. This guide walks through listing one, step by step, including the parts the docs leave out.

The comments in this guide are the dev talk: WHY explains, NOTE adds detail, GOTCHA marks a trap, TRIED is what I learned the hard way.

1. Before you start

  • A Rust MCP server that runs over stdio, on crates.io or ready for it.
  • A GitHub account.
  • mcp-publisher, the registry's own CLI.

terminal

brew install mcp-publisher

# or the release binary (macOS, Linux)
curl -L "https://github.com/modelcontextprotocol/registry/releases/latest/download/mcp-publisher_$(uname -s | tr '[:upper:]' '[:lower:]')_$(uname -m | sed 's/x86_64/amd64/;s/aarch64/arm64/').tar.gz" | tar xz mcp-publisher && sudo mv mcp-publisher /usr/local/bin/
NOTE: run mcp-publisher --help and look for validate and status in the list.Older builds don't have them, and this guide uses both.

2. Pick your server name

A server name is a namespace, a slash, and a name. If you log in with GitHub, your namespace is io.github. plus your username:

io.github.you/widget
WHY: the registry only lets you publish names in a namespace you've proved you own.GitHub login proves io.github.<your-username>.
GOTCHA: publishing under a GitHub org?The usual login can't do it yet: it only grants your personal namespace (registry issue #1468).You need to be an org Owner, then publish from GitHub Actions, or log in with a token that has read:org.
NOTE: own a domain?DNS login gives you names like com.example/widget instead.

3. Put the mcp-name: line in your README

This one line is how the registry knows the crate is yours. The registry docs suggest a bullet near your links:

README.md

# Widget MCP Server

A Rust MCP server for widgets.

- `mcp-name: io.github.you/widget`
WHY: crates.io renders your README to HTML on its CDN.The registry fetches that page and looks for the line.Only the crate's owner can publish that README, so finding the line is the proof.
GOTCHA: don't hide it in an HTML comment.<!-- mcp-name: ... --> works on PyPI and NuGet, but crates.io strips HTML comments when it renders, so the registry never sees it.Use visible text.
TRIED: crates.io strips comments!The hidden token simply vanished on crates.io.I learned the hard way, now you don't have to, as rust-faf-mcp 0.3.1 fixed it.
GOTCHA: the line is checked in the README of the exact crate version you list.That README is fixed when you cargo publish.Forgot the line?You'll need to publish a new crate version.
NOTE: the name has to end where your name ends. mcp-name: io.github.you/widget does not match inside io.github.you/widget-pro.Backticks are fine.

4. Write server.json

mcp-publisher init writes a starting file. In a Rust project, it needs editing:

GOTCHA: init reads package.json, not Cargo.toml.In a Rust repo it writes an npm entry with placeholders and a sample API-key variable.Change it to match the file below.

server.json

{
  "$schema": "https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json",
  "name": "io.github.you/widget",
  "title": "Widget",
  "description": "A Rust MCP server for widgets",
  "version": "0.3.0",
  "packages": [
    {
      "registryType": "cargo",
      "identifier": "widget",
      "version": "0.3.0",
      "transport": { "type": "stdio" }
    }
  ]
}
NOTE: identifier is your crate name. version is required for cargo: it says which crate version to check.Keep it equal to the top-level version.
NOTE: no runtimeHint for cargo. npm has npx, PyPI has uvx; cargo has no per-run runner.Users cargo install once; the client runs the binary.

Then check the file before you publish:

terminal

mcp-publisher validate
GOTCHA: validate checks the shape, not ownership.It doesn't fetch your README.I pointed it at a crate with no mcp-name line and got "server.json is valid".The real check comes at publish.

5. Publish the crate, then the listing

terminal

cargo publish
mcp-publisher login github
mcp-publisher publish
WHY: the order matters.The registry checks the README that crates.io already serves, so the crate goes first, then the listing.
NOTE: login github prints a code.Enter it at github.com/login/device, then come back.
GOTCHA: a published version is final.You can't change it or publish it again.A mistake means a new version number.
NOTE: crates.io sometimes rate-limits the check (429, or a 5xx).The error says it's likely temporary.Wait, then publish again.

6. Check it's listed

terminal

curl "https://registry.modelcontextprotocol.io/v0.1/servers?search=io.github.you/widget&version=latest"
NOTE: without version=latest, search returns every version you have ever published.
NOTE: the listing's status (active or deprecated) is in _meta, under io.modelcontextprotocol.registry/official.

7. Optional: npm and mcpb

packages is a list, so one server can ship several ways. Some Rust servers list cargo and npm together.

  • npm: put "mcpName": "io.github.you/widget" in package.json. No README line needed.
  • mcpb: a prebuilt binary from GitHub or GitLab Releases. The URL must contain mcp, and the entry needs a fileSha256 (openssl dgst -sha256 widget.mcpb).
WHY: cargo builds from source, so your users need Rust installed (rustup). mcpb needs no toolchain.The registry docs leave the choice to you.
NOTE: a cargo entry must not have fileSha256; the registry rejects it.That field is mcpb only.

8. Keep it current

For each release: publish the new crate version (the README line still in it), bump both version fields in server.json, then mcp-publisher publish.

To retire an old version:

terminal

mcp-publisher status --status deprecated \
  --message "Please upgrade to 0.4.0" \
  io.github.you/widget 0.3.0
NOTE: flags go before the name and version. --all-versions changes every version at once.

To publish from CI instead, the registry has a GitHub Actions guide. Its examples use npm; the registry steps are the same.
