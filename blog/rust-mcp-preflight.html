Rust MCP Preflight

Check an MCP Registry listing before you publish it

Tool · Nov 9, 2026 · Blog

mcp-publisher validate checks the shape of server.json. It doesn't check that the registry will accept your server. That happens at mcp-publisher publish, and for a Rust server it comes after cargo publish, when the crate version on crates.io is final. A missing README line at that point costs a new version number.

Rust MCP Preflight runs the registry's publish checks first. It's a CLI for your terminal or CI, and an MCP server your agent can call.

What it checks

  • The README line. It fetches the README crates.io serves for that exact crate version and looks for mcp-name: <your server name>, matched the way the registry matches it. It catches the line hidden in an HTML comment (crates.io strips comments), the line glued to the next word, and the wrong case.
  • server.json. The rules publish applies: $schema, the name, exact package versions (no latest, no ranges), the transport, and for cargo packages no fileSha256.
  • The server name. The name rules, whether it's already listed, and which login its namespace needs, including GitHub organizations, which login github can't publish to yet.
  • The namespace login (new in 0.2.0). For a domain namespace such as com.example/widget: is a public key published where mcp-publisher login dns or login http will look, and would the registry accept it?

New in 0.2.0: the namespace login

A domain namespace proves you own the domain with a key: a v=MCPv1; k=…; p=… TXT record, or the same line at https://<domain>/.well-known/mcp-registry-auth. Until now the first thing to check it was mcp-publisher login itself. Preflight reads it before you log in, with the registry's own rules:

  • DNS at the domain or a parent domain; HTTP only at that exact domain, with no redirects and at most 4096 bytes.
  • Ed25519 and ECDSA P-384 keys parsed as the registry parses them, down to Go's whitespace and base64 rules.
  • A record left at _mcp-auth. or _mcp-registry. named, with where to move it.

rust-mcp-preflight 0.2.0 · check_name com.example/widget

Server name
  FAIL  namespace com.example: no published key for `mcp-publisher login dns`
        or `login http`. Add a TXT record `v=MCPv1; k=ed25519; p=<public key>`
        at the apex of example.com (DNS also works from a parent domain), or
        serve it at https://example.com/.well-known/mcp-registry-auth.
        https://modelcontextprotocol.io/registry/authentication
  PASS  com.example/widget isn't listed yet: first publish

Not ready: 1 failure(s), 0 warning(s).

With a key in place, the same check prints PASS, the mcp-publisher login command that will work, and the key's fingerprint. Preflight can't see your private key, so when publish says a signature doesn't verify, compare that fingerprint with yours.

NOTE: if DNS can't be read (offline, a timeout), the check fails and says the login wasn't checked.A CI run never passes on a key it didn't see.

Try it

terminal

# prebuilt (needs cargo-binstall): Linux, macOS, Windows
cargo binstall rust-mcp-preflight

# or from source (Rust 1.88 or newer, a few minutes)
cargo install rust-mcp-preflight

rust-mcp-preflight server.json

It exits 0 when ready, 1 if anything fails, and 2 if the file can't be read. To give it to an agent, run it with no arguments as a stdio MCP server, for example claude mcp add preflight -- rust-mcp-preflight. The README has setup for goose, VS Code and Cursor too.

How it was checked

Every rule is ported from the registry's source, not its docs: the cargo validator, and for 0.2.0 the auth handlers (common.go, dns.go, http.go). The 58 tests run on stable Rust and on 1.88, the minimum version. The namespace check was run against published servers in three separate samples (15, 19 and 11 domain namespaces), and each result matched what the registry decides.

0.2.0 also had two outside reviews before merge, then a second round on the fixes. The second round caught a mistake in the first round of fixes. A reviewer had suggested a warning, not a failure, when DNS can't be read, and I took it. In this tool a warning means Ready, exit 0, so an offline CI run would have passed a namespace it never checked. It's a failure now, with every reason and a note to run again.

TRIED: a fix from a review is new code. It gets reviewed too.

Where it fits

cargo publish (with the README line), then rust-mcp-preflight server.json, then mcp-publisher login and mcp-publisher publish. The full walk-through is Listing a Rust MCP server in the official MCP Registry.
